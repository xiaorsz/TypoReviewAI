## 保留的原有功能

- 首页与每日学习统计、逐题正式复习、连续听写后统一判卷、撤销判定、遗忘曲线调度、重点错项和复习记录。
- 听写／背诵计划新增、编辑、批量录入、日期安排、预习、自动朗读、可调间隔、暂停重读、进度恢复、统一判定与错项跟进。

## AI 词语讲解：每组 5 个，学完再推荐

本地新增（2026-10-31，尚未发布）：在现有“组成与记忆”便签中增加“按读音记”，帮助孩子把声音和写法联系起来。中文可结合带声调拼音、字义及字形，英文可结合可靠的音节、重音及对应拼写；不机械拆分、不使用中文谐音替代英语发音，不确定时允许省略。它是记忆方法，不改变朗读按钮或播放行为。学习讲解、作答结果和学习记录详情共用这部分内容，作答页隐藏。随每词原有单次 AI 请求生成，旧讲解继续保留，不自动重新请求；基础讲解不编造读音提示。新增信息仍只保存在本机讲解元数据中。

本地同时修复具体单词页进入时的中间画面切换：展示前先确定续学位置、讲解／作答状态和基础模式，已有讲解直接显示；未准备的词保持准备画面，结束后才显示内容或失败提示。返回与下一词也同步切换词语和页面，不在后续异步任务中再次跳转。全屏背景使用学习页的语义颜色，移除整页切词淡出动画，避免过渡叠影。

生成方式：当前词先准备并显示，阅读时只在后台预备紧接着的下一个未跳过词；进入下一词后，再预备它的下一词。每次请求只处理一个词，已保存内容不重复生成；基础模式不调用 AI 预备。后台准备不禁用当前作答，提前切词会等待同一个进行中的请求。下一词失败只影响该词，可显式重试或使用基础讲解；退出、后台、恢复备份或来源变化会停止旧任务。尚未测量真实模型的首词或下一词等待时间，预备完成前切词仍可能需要等待。

学习页左上角支持返回：作答返回当前词讲解，结果页回看讲解，后续词可回到前面已准备的词；右上角单独退出。作答返回后保留本次输入，已提交结果只读回看，不重新判定；回看讲解后再提交会标记已回看。退出重进继续未完成小组。

词语／单词标题与例句旁提供独立朗读按钮，英文例句的中文翻译也可单独朗读。按题目科目使用中文或英语系统语音，按钮支持暂停和继续，并提供停止操作；一次只读一段，切换内容不会叠加排队。进入作答、切换词语、返回、退出、切到后台或音频中断时停止，学习记录详情同样可听读。 进度与朗读状态合并为一行，空闲不显示额外说明。词语旁的小喇叭可原位暂停／继续，例句的播放／暂停放在句子正文右上侧，中文翻译同样可单独听读；控件保留至少 44 点触控区域，切换状态不会让卡片或例句跳动。朗读不调用 AI、不申请麦克风权限，不自动播报作答答案。

界面的背景、卡片、正文与主色沿用首页和题库的语义颜色，浅色和深色随系统切换；保留更轻松的学习卡片排版：入口为词语卡片，讲解全屏展示，词义以更醒目的字号和字重显示，组成／记忆提示采用紧凑的浅色便签，例句以侧线和正文排版区分；作答、下一词与再学一组固定在底部。学习记录沿用同一视觉风格。支持深色模式、大字、标签自动换行及减少动态效果设置。书签小角色用 SwiftUI 绘制，无需额外图片资源。

首页和 AI 教练页提供“AI 词语讲解”。孩子可以自行完成，不需要家长逐组核题或逐题判定；家长仅需首次保存科目、AI 授权与 Key。

1. **推荐重点词**：近 30 天至少错 3 次、跨 2 天，支持语文字词和英语单词。每组最多 5 个，优先后续又错的词，再按错误次数、最近错误日期排序。同一天不重复推荐；不足 5 个按实际展示，学完没有新词就明确提示。
2. **讲明白再作答**：一次只准备一个词，讲词义、组成或拼写特点，并给出一个例句（英文附中文意思）。没有可靠结构知识时不强行拆分。每个词只出一道输入题；作答页隐藏讲解和标准答案，由程序核对，保留大小写差异。
3. **继续下一组**：完成后显示本组完成量和答对数量，可直接“再学 5 个”；返回或重启后优先继续未完成小组，已准备的内容不重复请求。中途改用基础讲解的选择也会保存。
4. **生成与失败处理**：每次模型请求准备一个词，已保存讲解不重复请求，阅读时后台只预备下一词。无安排工具，使用原题答案。程序校验内容长度、必填说明、翻译、题干遮盖及答案一致性；失败可重试、跳过或显式使用题库／词典基础释义。基础讲解不冒充 AI，不编造结构或例句。讲解有问题可直接跳过。
5. **后续观察**：屏幕作答不证明实际书写或已经掌握，不改变正式成绩、积分、阶段与每日题量。完成后的不同日期正常复习／听写作为独立证据，两个日期正确只标“有改善迹象”，有新错误会影响下次推荐与讲解。详情及旧版纸上补练保留在“学习记录”。

分析在打开页面后后台读取原生快照，推荐结果缓存供界面使用，不在首页或设置页扫描历史。元数据升级到 v2，兼容 v1 记录与原生日期精度，原子写入。恢复备份会重置本机补练关联；来源撤销、内容改变、授权变更及取消会阻止迟到响应保存。

**存储范围**：讲解、学习组及补练元数据仅在当前实验设备保存，暂未加入 iCloud 或备份导出；正式题库与学习记录继续同步。没有新增 SwiftData 模型或 CloudKit 字段。AI 内容的真实教学质量仍需试用反馈；程序校验不能保证所有词义和结构解释都正确。

## 新增 AI 教练

首页已移除独立的“AI 复习安排／规则复习安排”卡片、题目预览、选题依据及检查按钮，其余模块顺序保持不变；“开始今天复习”和其中的“预习内容”仍在原位置。“AI 词语讲解”继续保留。AI 自动安排、规则兜底及已保存题单不受影响；每日安排、选题依据和执行记录保留在设置中的 AI 教练页。

首页不显示 iCloud 状态卡片，状态检查与诊断保留在“设置 → iCloud 存储”中。CloudKit 默认自动同步，手动检查只查询状态。实验版未启用旧服务器同步路径时，不再创建该任务，避免它取消启动／回前台的自动状态检查。

各主页面左上角及“设置”提供 **AI 教练** 入口：

1. 在完整应用内录入题库，或通过设置的“备份管理”恢复原 App 导出的 JSON。
2. 在 AI 教练中填写独立的 DeepSeek API Key，选择科目、每日题量并授权。点击检查会先保存当前 Key，供后续自动安排使用。
3. 点击“检查记录并安排复习”。AI 查询真实题库、历史和已有安排，选择目标日期已到期的题目并排序。
4. AI 结果直接替换首页的“每日复习计划”，首页与看板使用同一份清单，不再创建第二套听写计划。选择“全部科目”可统筹汉字、词语、英语单词和背诵；选择单科时，其余科目按原规则补入同一个总上限。
5. 从首页“开始今天复习”使用原有逐题／统一判卷流程。进入复习后锁定本日清单，AI 不能中途改题。
6. 听写仍是独立的新内容录入和判定入口，不占每日复习题量。判定后沿用原有阶段与间隔进入后续复习；AI 根据新结果安排明天及之后已到期的内容。恢复备份不会将历史重新判定或计分。

每日复习题量与设置共用一个上限（1–50），统计所有科目，包含当天已完成的复习。程序按内容去重；当天已复习或已听写判定的内容，不会再次自动排入复习。原规则负责阶段推进和到期日期，AI 只能选题与排序，不能修改阶段、答案或积分。AI 可少选题，系统不会自动补成另一批。

单科授权时，AI 未选中的本科题不会自动补回；其他科目的到期题按原规则补入剩余名额，即使它们排在原规则前一批题量以外。已经完成的复习计入总量，当天已听写判定的内容继续排除。

没有 Key、断网、额度／接口错误或未生成有效计划时，已保存的清单保留；没有 AI 清单的日期按原有到期顺序生成复习。AI 运行时可先使用规则清单，开始练习后不再被迟到响应覆盖。提交前还会重新检查同步来的完成记录和剩余题量。

每次模型调用最多四轮。写入前、网络返回后及提交判定前校验题目 ID、科目、到期日、题量和重复内容。模型根据真实对错与错误频率给出依据，不推断未提供的错写字形；尚未用真实家庭样本验证选题质量或学习效果。

升级前版本已经存在的听写计划和判定均保留，不会因改变 AI 安排方式而删除。此前 AI 听写的本机规划关联会停止使用，新生成的 AI 复习清单写入可同步的 `ReviewDailyPlan`。

AI 教练、今日小结与练习小结共用本实验版的本机 Key；不读取原 App 的 Key，不经 iCloud 钥匙串同步。真实调用由所填 Key 的账户计费。

## 设置页性能调整

设置首页保留基本资料、复习模式、AI 教练、iCloud、备份和积分入口。AI 小结及晨读的详细选项分别进入“AI 小结与 API Key”“晨读与看板”后加载；原有选项和已保存配置不变。

设置首页不读取钥匙串。API Key 在小结子页面后台读取，保存和清空同样不阻塞主线程；不再保留已禁用的旧配对码读取。晨读旧格式单时间段使用稳定 ID，避免滚动或编辑时反复重建行，也保证修改能找到原时间段。设置快照直接使用值类型，显示所需临时模型按配置复用。

### AI 教练页响应与重试

教练页进入时只显示配置和最近 8 份未来安排，不扫描学习历史；本机 Key 后台读取，执行日志点开后才加载。点击“检查记录并安排复习”会采用当前页面的授权与设置，立即显示准备进度，再在后台读取原生学习数据。未授权、缺 Key、今日已开始锁定、模型调用失败等均有明确提示。

手动检查允许重新查询当天安排，自动触发继续去重；重查不会覆盖已开始的练习或创建重复计划。模型生成的计划成功写入原生数据库后才确认本轮反馈完成，失败后仍能重试。取消和备份恢复会使旧请求失效，迟到快照不会写回新数据集。

没有合法到期内容或剩余额度时，程序直接说明无需新增复习，不再反复报安排失败；判定后的检查覆盖未来 7 天。只向模型发送所选科目的题目与结果，其他科目的总题量使用匿名数字统计。教练和小结共享的 Key 读取、保存、清空及连接测试互斥，连接结果不会恢复旧 Key；往返教练子页面不会丢失未保存配置。

复习反馈只依据本次实际保存的判定，重复通知不会重复安排。撤回完成判定会停止旧反馈，撤销本次生成且未开始、未被后来修改的安排；新判定后再调整。模型返回后再次核验记录，已删除或更改的旧结果不会用于写入后续清单。

大题库下，反馈查询先返回本次错题、再返回本次其他判定，避免新判定被旧积压挤出首屏。也支持按题目 ID 定向读取真实历史，仍校验科目、存在性和查询资格；不把未读分页当成题目丢失。虚拟教练反馈不作为听写判定占用当天内容，跨午夜处理也按原始复习记录日期去重。

同步诊断按账户、区域、模型字段三个阶段报告，覆盖 17 类原生模型及 AI 清单新增字段。账户可用不代表同步完成，区域失败也不能直接断言缺字段。错误详情仅展开必要原因并隐藏凭据。

TestFlight 使用生产环境。2026-10-29 晚间控制台核对发现，实验版 Development／Production 只有系统 Users，缺少应用结构。根据本地实际模型导出 17 类、170 个属性，生成可复查的 `tools/cloud-schema/CoachLab.ckdb`。2026-10-30 用户明确授权后，该文件已通过 Apple 校验、导入 Development 并部署 Production；差异仅新增 17 类及 17 个记录 ID 索引，无删除及角色变更。已读回生产类型和 AI 清单字段；没有上传学习记录或 Key，没有操作原 App 容器。生成方式及范围见 `tools/cloud-schema/README.md`。手机需重新打开实验版检查 setup／export／import，同步是否恢复以设备事件及双机结果为准。

AI 的学习数据快照使用直接字段映射，保留原始 ID 和日期精度，避免主线程 JSON 往返。`lab.json` 现在仅保存教练配置、规划、日志和待处理反馈；原生学习历史仍完整保存在 SwiftData。首次运行仍兼容之前实验版缓存的一次性迁入。

## 独立与兼容

- 工程仍为 `CoachLab.xcodeproj`，scheme 为 `CoachLab`，应用标识仍是 `cc.xiaorsz.dictation-coach-lab`，可直接升级之前安装的实验版。
- 原应用的工程和源文件保持不变；本目录内保留独立代码副本。
- 主数据继续保存在本实验 App 沙盒的 `Library/Application Support/coach-full.store`，同时通过 SwiftData 的私有 CloudKit 数据库同步到 **`iCloud.cc.xiaorsz.dictation-coach-lab`**。原应用线上同步入口仍固定为不可用。
- 各设备登录同一 Apple ID 并开启 iCloud 后，可同步题库、听写、复习记录、任务、日程、积分和原生设置。设置页提供 iCloud 账户状态与同步诊断。
- 首次开启前会复制当前数据库与 SQLite 侧车文件到 `Library/Application Support/CloudMigrationBackups/`，不删除原文件；成功打开云配置后记录迁移完成。初始化失败会先尝试同一个本机数据库，避免丢失已有数据。
- 新导入的音视频优先保存在本实验版独立的 iCloud Documents 容器；iCloud 不可用时使用本机目录。旧本机文件仍保留，可在资源库重新导入以便上传。没有原应用的 App Group 或共享钥匙串权限。
- AI 的设置、日志和规划快照仍保存在本 App 的 `Library/Application Support/cc.xiaorsz.dictation-coach-lab/lab.json`。原生 SwiftData 为学习数据的事实来源；AI 元数据不会把旧快照覆盖回学习记录。
- 升级时，如果新主库为空且尚未完成迁移，会先一次性迁入先前精简实验版已保存的题库、复习记录、听写计划和判定。用户导入的原始 JSON 备份始终只读；本实验版的 AI 缓存会在迁移后改为仅保存元数据。
- 精简版此前跳过的任务、日程、积分等不在它的数据库中。如要一起带入，请在完整实验版通过原始 JSON 备份恢复；恢复会替换本实验版现有数据，确认前请自行导出备份。
- 原备份只包含音视频资源索引，不包含原 App 沙盒里的音视频文件。缺失的实际文件需在新 App 的资源库重新导入。
- 不连接原 App 的 iCloud、服务器或小组件容器。AI 教练授权、API Key、执行日志和规划快照仍为本设备设置；实际生成的每日复习清单（含选题依据、开始锁定状态）与学习结果可经 iCloud 同步。

### 运行 iCloud 版

在 Xcode 选择 `CoachLab`，重新运行并安装新版。进入“设置 → iCloud 存储 → 检查 iCloud 同步状态”，在第二台登录相同 Apple ID 的设备上安装同环境版本后，检查新增题目和听写是否同步。调试构建使用 Development 环境，发布配置使用 Production。

独立容器权限已由 Apple 开发描述文件授权，并完成真机目标签名构建；尚未执行双真机端到端同步。实现方式遵循 [Apple 的 SwiftData iCloud 同步说明](https://developer.apple.com/documentation/swiftdata/syncing-model-data-across-a-persons-devices)。
