# 听写 AI 教练 · 独立实验版

面向小学生家庭的 iPhone / iPad 测试 App。家长授权科目和每日题量后，AI 查询真实学习记录、创建听写计划，结合家长判定调整后续练习。

## 与原 App 的关系

- 独立工程：打开本目录的 `CoachLab.xcodeproj`，选择 `CoachLab` scheme。
- 独立应用标识：`cc.xiaorsz.dictation-coach-lab`；版本 `0.1.0 (1)`。
- 本机存储，无共享 App Group、iCloud、原应用同步服务或小组件。
- 复用的规则与听写逻辑以代码副本形式存在于本目录，不引用原工程源码。
- 应用状态保存在新 App 沙盒的 `Library/Application Support/cc.xiaorsz.dictation-coach-lab/lab.json`，采用先编码、原子写盘成功后更新界面状态的方式。
- DeepSeek Key 使用独立 Keychain service，仅本机保存，不读取原 App 的 Key。

## 开始使用

1. 在原“听写复习本”的**设置 → 备份管理 → 导出备份**保存 JSON 文件。
2. 在新 App 的**设置 → 导入听写复习本备份**中选择该文件，核对时间与条目数量，再确认替换实验数据。
3. 填写并保存新 App 自己的 DeepSeek API Key。不要将 Key 放入源码、备份或试用反馈。
4. 选择语文或英语、每日题量，开启授权并点击“保存设置并授权教练”。
5. 在“今日教练”查看选题依据，开始听写。孩子纸上书写，家长逐项确认对错并提交。
6. 查看已保存的后续计划和教练执行记录。网络失败时可重试，已保存的计划与判定保留。

默认模型为官方 `deepseek-flash`，也可选择 `deepseek-v4-pro`。每轮请求超时 45 秒，每次运行最多四轮模型请求，每轮最多六个工具调用。本轮不做网络自动重试；再次打开应用或手动重试可以重新触发未完成的安排。调用由所填 Key 的账户计费。

## 数据导入规则

- 支持 v1–v5 JSON 备份，兼容 ISO-8601 整秒及小数秒日期、旧版缺失的听写进度字段。
- 复制字词与英语单词题库、复习历史、听写计划及判定；保留 ID、日期和记录关联。
- 跳过英语背诵等首版不支持的类型及其历史。任务、日程、媒体、计算和积分不进入实验版。
- 设置只采用孩子姓名和每日题量；导入后教练保持关闭，需要重新授权。
- 缺少对应题目的历史复习记录、缺少对应计划的听写条目会跳过；导入确认前分别显示数量，其余有效关联完整保留，不猜测或补造缺失的题目和计划。
- 重复 ID、不合法对错值、损坏文件和未知版本仍会拒绝导入。失败不会替换现有实验数据。
- 再次导入会替换实验版题库、历史、计划和日志。源文件只读，原应用数据不变。
- 导入的已完成练习仅用于分析，不进入新判定事件队列。未完成的旧听写可以继续。
- 首版最大备份 50 MB，实验版题量为每天 1–30 题；超出范围的旧设置会收敛到此范围。

## AI 如何采取行动

工具调用基于 [DeepSeek 官方 Tool Calls 协议](https://api-docs.deepseek.com/guides/tool_calls/)，采用关闭思考模式的 Chat Completions 请求。工具执行在本机，模型本身无法直接改写数据库。

| 工具 | 能力 |
|---|---|
| `query_history` | 分页读取授权科目的题目、阶段、错误统计与最近八条复习历史 |
| `query_plans` | 查看已有听写安排、开始／取消／判定状态与题目 |
| `upsert_plan` | 使用本次已查询的题目 ID 创建或调整尚未开始的 AI 计划 |

写入必须先查询历史和已有安排，并通过本地校验。每天每个科目只保留一个 AI 计划槽位；同一天不同 AI 科目的总题量仍受每日上限约束。已开始、已完成、已取消的槽位不会自动覆盖或重建。手动计划不能被工具修改。同内容的不同题目 ID 也不能在同日重复安排。

普通安排可从今天起至未来七天；新判定后的补练最早从明天开始。基础阶段更新沿用原调度器的间隔和推进／回退规则；AI 不直接修改阶段。已有手动练习不计入 AI 题量，但其中出现的内容同日不再被 AI 重复安排。

调用与判定事件有持久化去重；判定只提交一次。新判定等待处理时，下一次打开 App 会继续处理。暂停、切换科目、导入或清空数据时取消进行中的教练任务，过期响应不能继续写入新数据集。

只有对错记录时，AI 依据错误频率和练习表现安排内容，不推断孩子具体写错的字形。教练的文本说明仍需家长判断；实际操作以已保存的计划和工具记录为准。

## 构建与验证

工程没有第三方依赖，部署目标为 iOS 17+，已使用本机 Xcode 27.1 构建。真机运行需在新工程选择自己的签名团队。实现过程中没有注册或发布新 App。

```sh
# 本目录执行；已有生成好的 Xcode 工程，通常不必重新生成
xcodegen generate --spec project.yml

# 本机核心测试：全部使用临时数据与模拟响应，不消耗 API 额度
swift test

# 检查原文件与运行配置隔离
python3 tools/verify_isolation.py

# iOS 模拟器构建
xcodebuild -project CoachLab.xcodeproj -scheme CoachLab \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath DerivedData CODE_SIGNING_ALLOWED=NO build
```

以上无签名命令仅用于编译检查；实际模拟器运行保留 Xcode 默认本地签名，系统钥匙串需要签名身份。模拟器命令行测试可使用 `CODE_SIGN_IDENTITY=-`，无需申请证书或注册新 App。

Xcode 的 Test 操作同时执行核心测试与界面测试。界面测试仅在 Debug 下使用 `--ui-testing` 参数，将数据保存到随机临时文件，API Key 也使用测试专用 service，不覆盖正常实验数据。

测试覆盖导入兼容与失败、原子保存、规则调度、重复提交及重启、工具权限与日期限制、暂停取消、四轮上限、AI 假成功拦截，以及计划写入后网络中断的恢复。
